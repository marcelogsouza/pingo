Contrato do dataset

JSONL: uma linha = um objeto JSON com content string não-vazia. Todo ingest (Wikipedia, CSV, HF) termina aqui. A QA usa as mesmas réguas do process_data.py (300+ chars, linhas curtas, símbolos, hash blake2b de duplicata). É o contrato do pré-treino — dataset de SFT (com pergunta/resposta) é reprovado aqui de propósito; ele entra direto na aba Treino.

Vocabulários existentes

tokenizer/ (default) tem 16.384 e é congelado — re-treinar invalidaria os data/tokens/*.bin antigos. Um vocabulário novo vira tokenizer/<id>/ e os tokens novos vão para data/tokens/<nome>/.

Binarizar dataset → tokens

Aplica o vocabulário escolhido ao JSONL e produz os shards .bin uint16 + meta.json (amarrado ao tokenizer — o train.py deriva o vocab dele, nunca digita à mão). O split val/train é o mesmo hash do process_data.py.

Pré-treino

O mesmo scripts/train.py da CLI. A época é contada sobre os tokens do meta.json do diretório de tokens escolhido.

SFT

O mesmo scripts/train_sft.py: parte do base escolhido, cresce o embedding se faltar token de chat e faz loss só na resposta. Os padrões são o run recomendado (1 época, lr 5e-5).

Job em andamento

O "parar" manda SIGTERM: o script fecha o step, grava o checkpoint e sai limpo — aí você marca "retomar" e continua exatamente dali.
